# دراسة تطوير لوحة تحكم العميل

## القرار التصميمي المقترح

تتحول لوحة العميل إلى **مركز اكتشاف وطلب ومحتوى** داخل صفحة واحدة، بدل توزيع القيمة على صفحات منفصلة. يظهر العميل المطاعم أولًا، ثم يرى الإجراءات الأساسية لكل مطعم، ثم ينتقل بصريًا إلى المحتوى الغذائي البارز دون أن يُجبر على دخول سوق مستقل. يبقى Trend Kitchen مفتوحًا وظاهرًا افتراضيًا، مع زر إخفاء يحفظ تفضيل العميل.

> الهدف ليس زيادة العناصر، بل ترتيبها حسب نية العميل: اكتشاف المطعم، مشاهدة معلوماته، الطلب أو الحجز، حفظه، ثم اكتشاف المحتوى والمكافآت.

## 1. دراسة الوضع الحالي والفجوات

| المجال | الملاحظة الحالية | الأثر على العميل | القرار المقترح |
|---|---|---|---|
| بطاقات المطاعم | المعلومات والإجراءات تبدو مزدحمة أو غير متوازنة. | صعوبة معرفة الخطوة التالية. | بطاقة موحدة بثلاث طبقات: الهوية، البيانات، الإجراءات. |
| هوية المطعم | الشعار موجود، لكن البيانات المساندة ليست بارزة بما يكفي. | ضعف الثقة قبل الطلب. | إظهار الشعار، الاسم، الحالة، رقم الجوال، العنوان، والرمز عند الحاجة. |
| الإجراءات | Menu والطلب والحجز لا تظهر دائمًا كأولوية واحدة. | تردد أو تنقل زائد. | ثلاثة أزرار أساسية ثابتة: Menu، اطلب، احجز. |
| المفضلة | تفضيل المطعم لا يظهر كمركز واضح. | فقدان المطاعم المفضلة بين القائمة العامة. | قسم مستقل للمطاعم المفضلة أعلى دليل المطاعم عند وجودها. |
| المحتوى | قد يظن العميل أن Trend Kitchen منيو أو صفحة منفصلة إلزامية. | التباس في نموذج الاستخدام. | شريط محتوى داخل البوابة بعنوان واضح: صور ووصفات وعروض غذائية. |
| الإخفاء | المحتوى ظاهر، لكن يحتاج تحكمًا بسيطًا. | قد يشعر العميل أن الصفحة مفروضة عليه. | زر إخفاء/إظهار يحفظ التفضيل دون حذف المحتوى. |
| معلومات التواصل | رقم الجوال والعنوان لا يظهران دائمًا في مستوى القرار. | صعوبة الاتصال أو معرفة الموقع. | عرض الجوال والعنوان في الجزء الثانوي من بطاقة المطعم. |
| الحساب | وجود إجراءات مثل تبديل الحساب قد يشتت العميل. | زيادة الحمل المعرفي. | الإبقاء على تسجيل الخروج، اللغة، الإشعارات، والخصوصية فقط في المسار الرئيسي. |
| اللغة | تبديل اللغة موجود ويجب أن يبقى قريبًا من الحساب. | عدم ملاءمة الواجهة لغير العربي. | وضع المبدّل في رأس لوحة العميل مع حفظ اللغة واتجاه RTL/LTR. |

## 2. شكل بطاقة المطعم المقترح

| الطبقة | العناصر | سبب وجودها | مستوى الظهور |
|---|---|---|---|
| الهوية | الشعار، الاسم، حالة النشاط، نوع المطبخ | تعريف سريع وبناء الثقة. | ظاهر دائمًا |
| البيانات | رقم الجوال، العنوان، الرياض أو المدينة، ساعات العمل المختصرة | مساعدة قرار الزيارة أو الطلب. | ظاهر في البطاقة الموسعة |
| الإجراءات | Menu، اطلب الآن، احجز | تقليل النقرات وتحويل الاهتمام إلى فعل. | أزرار أساسية ثابتة |
| العلاقة | إضافة للمفضلة، مشاركة آمنة، آخر زيارة | دعم العودة والانتشار العضوي. | ثانوي واضح |
| التعريف | QR أو رابط المطعم عند الحاجة | ربط البطاقة بالمنيو أو الملف العام. | قائمة ثانوية لا تطغى على الطلب |

يُفضّل أن تكون البطاقة في الهاتف عمودية، مع شعار بحجم ثابت، وعنوان لا يتجاوز سطرين، وأزرار الإجراءات بعرض متساوٍ. على سطح المكتب تُعرض البطاقات في شبكة مرنة من عمودين أو ثلاثة حسب العرض، دون ضغط النص أو إخفاء الأزرار الأساسية.

## 3. ترتيب صفحة العميل

| الترتيب | القسم | المحتوى | الإجراء الرئيسي |
|---:|---|---|---|
| 1 | رأس الحساب | الاسم، الصورة، اللغة، الإشعارات، تسجيل الخروج | تغيير اللغة أو الوصول للحساب |
| 2 | ملخص سريع | الطلب الحالي، الرصيد، المكافآت، حالة Studio | متابعة أهم حالة |
| 3 | المطاعم المفضلة | المطاعم التي حفظها العميل | فتح المطعم أو الطلب |
| 4 | دليل المطاعم | المطاعم النشطة مع البحث والفلاتر | اكتشاف مطعم |
| 5 | شريط المحتوى | صور ووصفات ومحتوى غذائي من العملاء | مشاهدة أو تفضيل أو مشاركة |
| 6 | Trend Kitchen | السوق ظاهر افتراضيًا وقابل للإخفاء | اكتشاف المحتوى التجاري |
| 7 | الخدمات | Studio، المكتبة، المزايا، الدعم، الخصوصية | إدارة الحساب والمحتوى |

هذا الترتيب يجعل المطاعم جزءًا من المهمة اليومية، ويجعل المحتوى مسار اكتشاف مستمرًا لا بوابة إجبارية. يجب ألا يختفي المحتوى بمجرد إغلاق السوق؛ بل يتغير إلى شريط مختصر يمكن إظهاره لاحقًا.

## 4. نموذج ظهور المحتوى بين المطاعم

| العنصر | التصميم المقترح | ضابط تجربة المستخدم |
|---|---|---|
| العنوان | «محتوى الطعام والوصفات» مع وصف قصير | يوضح أنه محتوى وليس Menu. |
| التبويبات | الأحدث، الأكثر تفضيلًا، وصفات، صور أطباق | عدد قليل من التبويبات القابلة للفهم. |
| البطاقة | صورة مائية، نوع المحتوى، الوسوم، حالة البيع | لا تعرض بيانات المطعم الخاصة أو بيانات العميل الحساسة. |
| الأزرار | مشاهدة، تفضيل، مشاركة، شراء عند الأهلية | زر واحد أساسي، والباقي ثانوي. |
| الإخفاء | «إخفاء المحتوى من الصفحة» | لا يلغي المفضلة أو المكتبة أو المشتريات. |
| العودة | «إظهار المحتوى مجددًا» من تفضيلات الحساب | استعادة بسيطة دون فقد البيانات. |

## 5. رحلة العميل المقترحة

| المرحلة | ما يراه العميل | النتيجة المطلوبة |
|---|---|---|
| الدخول | لوحة عربية أو باللغة المختارة، مع حسابه وحالته | يفهم أنه داخل حسابه فورًا. |
| الاكتشاف | مطاعم مفضلة ثم مطاعم نشطة مرتبة بوضوح | يجد خيارًا مناسبًا بسرعة. |
| القرار | شعار المطعم، الجوال، العنوان، Menu، الطلب، الحجز | يملك المعلومات اللازمة دون فتح صفحات كثيرة. |
| التفاعل | محتوى غذائي بارز بين الأقسام | يكتشف Trend Kitchen دون البحث. |
| الشراء | تنبيه أهلية واضح إن كان الحساب غير مؤهل | لا يواجه خطأ غامضًا، ويعرف كيف يتواصل مع الدعم. |
| بعد الطلب | حالة الطلب والمكافآت والمكتبة | يرى قيمة حسابه بعد العملية. |
| العودة | المفضلة، إعادة الطلب، محتوى جديد، مكافآت | تتكون عادة استخدام متكررة. |

## 6. فرص التسويق وحركة المنصة

| الفرصة | التنفيذ داخل لوحة العميل | القيمة التسويقية |
|---|---|---|
| اكتشاف محلي | ترتيب المطاعم حسب المدينة والقرب والنشاط | يرفع احتمال الطلب من مطعم قريب. |
| محتوى يومي | شريط صور ووصفات يتغير مع الحفاظ على الجودة | يعيد العميل إلى اللوحة حتى قبل الطلب. |
| توصيات غير مزعجة | اقتراح مطعم أو محتوى بناءً على المفضلة | يزيد الاكتشاف دون إزعاج. |
| مكافآت مرتبطة بالسلوك | مكافأة الطلب المتكرر أو حفظ مطعم أو مشاركة آمنة | تحول الاستخدام إلى عادة. |
| إحالة الأصدقاء | رابط دعوة لا يكشف بيانات العميل | نمو عضوي قابل للقياس. |
| مواسم الطعام | أقسام مؤقتة مثل رمضان أو الشتاء أو القهوة | دعم الحملات من غير إعادة بناء الصفحة. |
| قصص المطاعم | بطاقة قصيرة عن طبق أو مطبخ | تقوية العلاقة العاطفية مع المطعم. |
| محتوى العملاء | إظهار الصور المقبولة بعلامة مائية | صناعة سوق محتوى متخصص بالطعام. |
| تنبيهات ذكية | إشعار عند توفر محتوى أو مكافأة أو طلب | زيادة العودة مع احترام الموافقة. |
| عروض متدرجة | عرض الباقة أو الميزة عند لحظة الحاجة | تحسين التحويل دون بيع مبكر مربك. |
| مشاركة المطعم | رابط عام للمطعم أو Menu أو Profile | اكتساب زيارات خارجية. |
| قياس التحويل | تتبع ظهور البطاقة والنقر والطلب والحجز | معرفة ما يحقق قيمة فعلية. |

## 7. خطة التجزئة قبل التنفيذ

| المرحلة | النطاق | معيار القبول |
|---|---|---|
| A — الأساس | إعادة بناء بطاقة المطعم، الجوال، العنوان، الإجراءات، والمفضلة. | يستطيع العميل فتح Menu أو الطلب أو الحجز من البطاقة مباشرة. |
| B — المحتوى | شريط المحتوى المدمج، Trend Kitchen الظاهر، زر الإخفاء، والفصل البصري. | يظهر المحتوى داخل اللوحة ولا يخلطه العميل مع Menu. |
| C — العودة | إعادة الطلب، المفضلة، ملخص المكافآت، الإشعارات، وحالة Studio. | يجد العميل آخر إجراء أو قيمة له عند العودة. |
| D — النمو | التوصيات، المواسم، الإحالة، المشاركة، وقياس التحويل. | يمكن قياس مصدر الزيارة والطلب والعودة. |
| E — التخصيص | ترتيب شخصي للبطاقات، تفضيلات المحتوى، وإشعارات دقيقة. | تتغير التجربة حسب اختيار العميل دون كشف بيانات حساسة. |

## القرار النهائي قبل البرمجة

الأولوية ليست إضافة صفحة جديدة للسوق، بل **إعادة ترتيب لوحة العميل لتصبح واجهة موحدة**: المطاعم في مقدمة الاستخدام، والمحتوى ظاهر في طبقة اكتشاف مرنة، وTrend Kitchen مفتوح افتراضيًا وقابل للإخفاء. يجب تنفيذ المرحلة A ثم B قبل إضافة حملات التوصيات والإحالات؛ لأن التسويق لن ينجح إذا بقيت بطاقة المطعم نفسها صعبة القراءة أو إذا لم يعرف العميل الفرق بين Menu وسوق المحتوى.

جميع الميزات التي تتعامل مع الدفع أو المكافآت أو بيانات الموقع يجب أن تحافظ على سجل تدقيق، وموافقة العميل، وفصل الأموال، ومؤشرات واضحة للحالة. الدراسة تصميمية ومنتجية وليست بديلًا عن مراجعة الخصوصية أو الامتثال القانوني قبل الإطلاق التجاري.
