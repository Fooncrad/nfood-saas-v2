# نطاق تحليل المشاعر للتقييمات

## الحالة الحالية

نظام NFOOD يحفظ التقييمات منفصلة حسب الهدف: المطعم، السائق، والمنتج. يمكن للإدارة قراءة التقييمات وتصفيتها، ولا يتم تشغيل تحليل مشاعر أو توليد تصنيف آلي في الإصدار الحالي.

## سبب التأجيل

يتطلب تحليل المشاعر اعتماد نموذج LLM ومفتاح مزود وتحديد سياسة الاحتفاظ بالنصوص، إضافة إلى تحديد ما إذا كان التحليل يتم لحظة الحفظ أو عبر مهمة دورية. لا يجوز تصنيف المشاعر أو عرض مؤشرات تحليلية قبل اعتماد المزود وسياسة الخصوصية.

## متطلبات المرحلة المستقبلية

يجب إضافة حقل نتيجة منفصل عن نص العميل، مثل `sentimentLabel` و`sentimentScore` و`analyzedAt`، مع حفظ مصدر النموذج وإصدار السياسة. يجب أن يكون التحليل قابلاً لإعادة المحاولة وآمنًا من التكرار، وأن تظل صلاحية قراءة النص والنتيجة محكومة بعزل المطعم. لا يجوز تعديل النص الأصلي أو اختلاق تقييمات أو نتائج تحليل غير مستندة إلى تقييم محفوظ.

## معيار القبول

تُعد الميزة مكتملة فقط عند وجود إجراء backend محمي، واختبار يثبت العزل، وواجهة تعرض حالة التحليل `pending` أو `completed` أو `failed`، وتوثيق واضح للمزود والتكلفة وسياسة حذف النصوص.
