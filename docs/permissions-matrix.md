# مصفوفة الصلاحيات الحالية

هذه المصفوفة تميّز بين ما يحرسه backend فعلًا وما تحجبه الواجهة لتحسين التجربة. لا تُعدّ إخفاء الزر بديلًا عن الحارس الخلفي.

| المجال | إجراء رئيسي | حارس الواجهة | حارس backend | الحالة |
|---|---|---|---|---|
| الطلبات | إنشاء طلب جديد | `orders.create` يخفي الزر عن الأدوار غير المسموحة | `testRole`/حارس المطعم | مثبت ومختبر |
| الحجوزات | إنشاء حجز | `reservations.create` يخفي النموذج | حارس الإجراء في router | مثبت ومختبر |
| الطلبات/KDS | تحديث حالة الطلب | عرض الإجراءات حسب الدور | حارس الحالة وعزل المطعم | مثبت ومختبر |
| المنيو | إنشاء/تعديل/حذف صنف أو تصنيف | واجهات إدارة المطعم | `restaurant_admin` وعزل المطعم | مثبت بمصفوفة CRUD |
| المخزون والمشتريات | إجراءات الإدارة | تنقل المطعم | حراس المطعم/الدور | مثبت بمصفوفة الإجراءات |
| الفريق والتسويق | إدارة الموظفين والكوبونات | تنقل المطعم | حراس الملكية والدور | مثبت جزئيًا |
| Super Admin | إدارة المطاعم والاشتراكات | مسارات admin | `adminProcedure`/سياق مركزي | مثبت ومختبر |

## نطاق الفرع

العزل الحالي يفرض نطاق المطعم، وليس مصفوفة صلاحيات مستقلة لكل فرع. وجود `branchId` في بعض الإجراءات لا يعني أن المستخدم يملك branch scope؛ يجب تنفيذ هذا الحارس صراحة قبل إغلاق بند الصلاحيات الموسعة.

## حدود الاختبار

تغطي الاختبارات الحالية allow/deny للإجراءات الحساسة، CRUD persistence لموارد المنيو، وعزل المطعم. لا تدّعي هذه المصفوفة أن كل زر في كل وحدة يملك action policy مستقلة، ولا أن branch scope مكتمل.
