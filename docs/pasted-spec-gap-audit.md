# مراجعة مواصفات تطوير NFOOD

تمت مقارنة الملف المرفق بالمنصة الحالية مع الحفاظ على المسارات والجداول والعقود القائمة. يغطي المشروع بالفعل تعدد الأدوار، RTL/LTR، المنيو العام، POS وKDS، الفروع والطاولات، الحجوزات، السائقين، المخزون، التسويق، حالات التحميل والفراغ والخطأ، وعزل بيانات المطاعم.

| المجال | الحالة قبل هذه الدفعة | التحسين المنفذ |
|---|---|---|
| إضافات الصنف | إضافة مرتبطة بصنف مع سعر ومخزون وتوفر وترجمة | إضافة مجموعات، إلزام/اختيار، حد أدنى وأقصى، ترتيب، إدارة CSV، وتحقق خادمي |
| حفظ الإضافات | محفوظة في `selectedAddonsJson` داخل بنود الطلب | تم الحفاظ على التدفق الحالي دون تغيير عقد الطلب |
| لوحة السائق | الطلبات المعينة، الحالات، ETA، الرفض، الموقع والمحادثة | إضافة زر خروج واضح في الهيدر بحالة تحميل وإعادة توجيه للدخول |
| الصلاحيات | عزل أدوار وصفحات وإجراءات | الحفاظ على النموذج الحالي وعدم توسيع وصول السائق أو الأدوار الحساسة |
| الهوية والتجاوب | نظام ألوان وتخطيطات RTL/LTR ومتجاوبة | إعادة استخدام المكونات والتوكنات القائمة بدل إنشاء واجهات مكررة |

## مراحل لاحقة موصى بها

ربط مجموعة إضافات واحدة بعدة أصناف يحتاج جدولَي مجموعات وربط مستقلين بدل تكرار بيانات المجموعة. كما أن تطبيق قيود المجموعة في منيو العميل يحتاج تمرير حقول المجموعة في استعلام المنيو العام ثم فرضها قبل الإضافة للسلة. يفضّل تنفيذ ذلك كمهاجرة مستقلة مع اختبارات طلب وفاتورة وKDS.
