# خارطة الميزات المتقدمة المفتوحة

هذا المستند يحدد حدود التنفيذ الحالية للميزات التي تتطلب نموذج بيانات أو مزودًا خارجيًا أو تشغيلًا إنتاجيًا إضافيًا. وجود بند هنا لا يعني أن واجهة شكلية أو زرًا مؤقتًا سيُعامل كميزة مكتملة.

| المجال | الحالة الحالية | المتطلب التالي | معيار القبول |
|---|---|---|---|
| Google وApple وOTP وPasskey | Manus OAuth وتسجيل الدخول الاختباري يعملان، أما المزودات الإضافية فغير موصولة | مفاتيح OAuth ومزود OTP وWebAuthn/RP ID | تسجيل دخول واختبارات فشل ونجاح وإدارة جلسات دون كشف الأسرار |
| Birthday وRe-engagement وReferral | الحملات والكوبونات الأساسية موجودة، لكن لا يوجد ملف Customer مؤهل أو سجل إحالات | نموذج Customer وconsents وأحداث شراء مؤهلة وقواعد جدولة | لا تُرسل حملة إلا لشريحة مستوفية للشروط مع سجل تدقيق وإلغاء اشتراك |
| الولاء والتقييمات وتحليل المشاعر | لا توجد دورة تقييم موحدة مرتبطة بالطلب والسائق والمنتج | جداول تقييم وموافقة ومصدر تحليل مشاعر | فصل تقييم السائق عن المطعم والمنتج مع منع التقييمات الوهمية |
| الطابعات وأقسام المطبخ | KDS وحالات الطلب موجودة، لكن لا توجد وجهات طباعة أو قواعد توجيه | أقسام مطبخ وطابعات وقواعد routing ومحول طباعة | توجيه كل بند إلى القسم الصحيح مع retry وسجل فشل |
| Driver Workflow | دور السائق وحقول الطلب الأساسية موجودة، لكن لا توجد دورة تسليم كاملة | حالات توصيل ووثائق وETA ومبررات فشل | لا ينتقل الطلب إلى حالة غير مسموحة ويظهر السجل للسائق والمطعم |
| Custom Domain وLanding Page | PWA Branding وWhite Label لكل مطعم منفذان | DNS/verification mapping وقوالب landing قابلة للحفظ | تحقق ملكية النطاق وعزل إعدادات كل مطعم وfallback آمن |
| SLA وSupport Agent وAPI/Webhook | Remote Work والإشعارات الداخلية موجودة، لكن SLA وwebhook registry غير منفذة | سياسات SLA وقنوات دعم ومفاتيح API وسجل webhook | قياس زمن الاستجابة وإعادة المحاولة وتوقيع webhook وتدقيق الأحداث |
| SSO Enterprise | لا يوجد مزود SAML/OIDC مؤسسي موصول | metadata وclient credentials وسياسة domain discovery | دخول مؤسسي مع عزل المؤسسة وتسجيل الجلسة وإلغاء الوصول |

## قواعد التنفيذ

يجب إضافة أي سر جديد عبر إعدادات الأسرار، ولا تُكتب المفاتيح في الشيفرة أو الاختبارات. كما يجب أن تُضاف migrations عبر schema-first workflow وأن تُختبر إجراءات الحماية قبل ربط الواجهة. أي تكامل خارجي يحتاج مفاتيح أو حسابًا مؤسسيًا سيبقى في حالة **غير مكتمل** حتى يتم التحقق منه فعليًا.
